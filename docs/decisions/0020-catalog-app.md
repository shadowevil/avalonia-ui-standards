# 0020 — Catalog app

- **Status:** Agreed, 2026-11-12
- **Decision:**
  - A desktop app in `apps/Catalog` (project `Catalog`) for browsing and trying the library live. It is built with the solution and never shipped.
  - A simple sidebar list of pages, with no tier grouping.
  - Live theme controls in the window's toolbar band ([0043](0043-toolbar-band.md), which sets the item sizes, labels and the "…" menu), below the title band, which holds only the window buttons, the sidebar button and the title:
    - segmented controls for theme (System, Light, Dark), density (Normal, Compact), reduce motion and reduce transparency (each Follow OS, Reduced, Full). Motion and transparency each have a decorative leading icon: for motion the library's motion icon of the selected value (`Icons.MotionSystem`, `MotionReduced` or `MotionFull`, [0026](0026-icon.md)), swapped as the value changes; for transparency the Glass page's `Icons.Drop`; `SpacingS` before the segments, at the band's icon size and colour; it is part of the control, so it moves into the "…" menu with it and takes no focus;
    - the accent as an icon drop-down button ([0021](0021-button-siblings.md)) whose icon is a chip of the accent at the icon size, with a hairline edge and radius 4. It opens a menu ([0036](0036-menus-and-flyouts.md)): the presets (Default, Teal, Green, Orange, Purple, Pink), each with its chip in the icon column and the menu's check mark on the chosen one (one-of-many, kept by the catalog), then a separator and the hex box (#RRGGBB) as the last item, which stays open when clicked. In the "…" menu the drop-down is a submenu as 0043 describes; its last entry, "Custom colour…", opens the whole accent menu at the band's trailing end, right-aligned.
    - Theme and accent lead, then density as a group of its own; motion and transparency sit in the trailing zone, as two groups. As the window narrows they move into the "…" menu in the order transparency, motion, density, accent, theme, so theme and accent stay visible longest.
    - **Why:** Settings with a few options read best as segmented controls ([0032](0032-segmented-control.md)); the band gives them a row of their own and keeps every setting reachable at any width. Motion and transparency share their options, so the icons tell them apart. The accent has more choices than fit in a band, so the band shows the current colour and the choices open as a menu; the chevron shows the button opens one. A check mark rather than the radio dot marks the chosen preset: it shows the chosen colour without a selection fill.
  - Every control page shows its variants × states side by side (rest, hover, pressed, disabled, focused) next to a live row.
  - Style pages show the actual theme values.
  - The Glass page also shows an opaque card in the window's glass panel (marked with `OpaqueRegion.IsOpaque`, with a switch to unmark it) and a live readout of the window's `BackdropVisibleRegion`: its number of rectangles and the share of the frame they cover ([0015](0015-glass.md), [0022](0022-window-layout.md)).
  - It uses the library as apps do ([0017](0017-app-usage.md)).
  - It uses only library controls once they exist. It moves into the window of [0022](0022-window-layout.md) once the window frame, title band, content panel and status bar are done; its sidebar is the `Sidebar` Module ([0034](0034-sidebar.md)), one row per page with an icon from `Icons`.
  - The test project renders every catalog page (full height) to PNG, in light and dark.
  - The catalog has an animated ribbon backdrop, placed in `StandardsWindow`'s `Backdrop` slot ([0022](0022-window-layout.md)). It is simple ribbons undulating in place in a seamless 45 s loop (no sideways scroll), tinted from the accent, with 2–3 thin glowing edge lines per ribbon whose brightness varies smoothly along their length with dark gaps, and twinkling sparkles near the lit edges. It is driven by `StandardsWindow.FrameTick` ([0016](0016-motion.md)), so it is frozen under reduce motion and paused when the window is inactive or minimised. It is catalog-only, a deliberate exception to "uses only library controls". Outside the glass panel, a scrim in the page colour keeps text at AA: strength 0.45 in light (5.48:1 measured) and 0.64 in dark (5.36:1 measured).
  - In light, the ribbons use normal blending: accent bands at opacity 0.5, accent lines deeper than the bands with wider halos, and sparkles with a ringed halo. Additive blending washed out to white on the light backdrop, so light uses normal blending and deeper tones to keep the ribbons visible.
  - The status bar is the `StatusBar` Module ([0047](0047-status-bar.md)): the page's name as the message; in the trailing zone the window's rendered frames per second (counted passively, so it causes no frames) and the effective `HighRefreshRate` ([0016](0016-motion.md)), or why animation is paused, with shorter forms the bar takes when the window is narrow; then the library version, which hides first when there is still no room.
  - A Settings page (`Icons.Gear`) is the sidebar's footer row ([0034](0034-sidebar.md)), pinned below the page list. It holds the catalog's settings: a switch for high refresh rate, which sets `StandardsTheme.HighRefreshRate` app-wide, and "Layout mode", a segmented control (Automatic, macOS, Windows) with the caption "The window layout the catalog shows: its window buttons, menu bar and title band. Automatic uses this computer's; macOS and Windows show that system's on any computer.", which sets the main window's `LayoutMode` ([0022](0022-window-layout.md)) at once.
    - **Why:** The catalog is developed on macOS; the layout mode shows the Windows layout, with its caption buttons and menu row, there.
  - The catalog reopens as it was left: the toolbar band's choices (theme, density, accent, reduce motion, reduce transparency) and the Settings page's (high refresh rate, layout mode as `LayoutMode`) are saved, half a second after the last change, to `AvaloniaUiStandards.Catalog/settings.json` (System.Text.Json) in the per-user application data folder (`Environment.SpecialFolder.ApplicationData`: ~/Library/Application Support on macOS, %APPDATA% on Windows, ~/.config on Linux), and applied at startup. A missing or unreadable file gives the defaults.
  - A test also drives the catalog's main window through every page and toolbar band setting, as a regression guard.
  - The catalog sets its own application name, "Avalonia UI Standards Catalog", and its own application menu with an "About Avalonia UI Standards Catalog" item that opens a small window with the name and library version. This replaces the default "About Avalonia" item on macOS; Quit, Hide and Services come from Avalonia. In the Windows layout the About item joins the end of the Help menu in the menu row ([0044](0044-menu-bar.md)).
  - The main window has a menu ([0044](0044-menu-bar.md)) with harmless, working entries: File (Close window), Edit (Undo, Redo, Cut, Copy, Paste, Select all, acting on the focused text box, with the platform's command key gestures; enabled only while a text box has focus, the one they act on, so they are greyed out when there is nothing to act on), View (Theme and Density as radio items in step with the toolbar band; Next page and Previous page, command key with Page Down and Page Up; the library's full screen item on macOS, [0049](0049-full-screen.md)) and Help (Show the settings file location, which opens the folder holding settings.json).
    - **Why:** The catalog shows the menu row and the system menu bar with a real menu, and the entries do what they say.
  - Each new Block adds its page as part of its own step.
  - Web ([0045](0045-web-library.md)): `web/catalog/` is one page with hash routes (`#button`), the desktop's pages for the Blocks and Modules that exist on the web, in its order, the ribbons in the shell's `Backdrop` slot, the `Sidebar` Module with the sidebar button in the title band, the menu row Module, the toolbar band Module holding the theme controls as on desktop (segmented controls, the accent drop-down with its hex box, the "…" menu), and the `StatusBar` Module showing the page name and the library version (a constant in `catalog.js`, checked against the project file by `web/tools/test.py`). Differences:
    - The toolbar band also has a glass quality segmented control (Full, Minimal, Solid) in the trailing zone, which the desktop does not have; it moves into the "…" menu first.
    - A Sidebar page, after the desktop's pages, shows the Module's stages side by side.
    - The choices are saved in `localStorage`, half a second after the last change.
    - There is no Settings page, and the status bar shows no frame rate; the ribbons pause only while the page is hidden.
    - The menu row has Edit, View, whose Full screen check item ([0049](0049-full-screen.md)) shows on every OS where the page can go full screen, unlike the desktop's macOS-only item, and the About item at the end of a Help title; the browser owns the window and the settings are in `localStorage`, so there is no File menu or settings file location. About opens a dialog in the page.
    - Page titles read "<Page> - Avalonia UI Standards Catalog". `?render` lays a page out for `web/tools/render.py`, which renders every page in light and dark, full height, at 1000 and 620 px.
- **Why:** It is a place to see and try everything live, across themes and settings, while the test renders ([0009](0009-screenshots-from-tests.md)) remain the reproducible record.
