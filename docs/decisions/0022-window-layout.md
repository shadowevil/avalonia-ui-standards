# 0022 — Window layout

- **Status:** Agreed, 2026-11-12. macOS native behaviour revised 2026-11-13: `BorderOnly` instead of a borderless window with `hasShadow`, because a borderless window gets only a tight shadow and `BeginResizeDrag` does nothing on macOS, so a borderless window cannot be resized.
- **Decision:**
  - Window frame:
    - The library draws its own window frame: a transparent window shaped as a squircle (radius 16, `CornerRadiusOverlay`; [0014](0014-shape.md)), except on Windows, with a soft shadow and a 1 px border. The window is borderless except on Windows and macOS; the shadow differs per OS (see Native behaviour per OS).
    - Window buttons are drawn by the library, styled per OS: traffic lights on the left on macOS, caption buttons on the right on Windows and Linux.
    - Drag, resize, minimise, maximise and close are handled natively where each OS allows it (see Native behaviour per OS).
  - Native behaviour per OS (macOS done in M3 step 6; Windows and Linux in a later step):
    - macOS (done): a titled, resizable, non-opaque window with its title bar and system buttons hidden (`WindowDecorations.BorderOnly`), used when running in a native macOS window (headless renders keep the drawn frame).
      - The system window shadow, the same as other apps' titled windows, derived from the content's alpha, so it follows the squircle. No drawn shadow and no margin: the window is exactly the visible frame, so tiling and positions use it.
      - The system's window corner mask (smaller than the 16 px squircle) does not clip the squircle, and the system adds no hairline of its own; the 1 px border stays the library's.
      - Native resizing from the edges and corners, with the system cursors; the library's resize grips are hidden.
      - Dragging the title band calls Avalonia's move drag, the same native window drag the `TitleBar` role starts. Double-clicking it follows the system setting "Double-click a window's title bar to" (`AppleActionOnDoubleClick`): minimise, do nothing, or otherwise maximise and restore.
      - The client area is not extended (`ExtendClientAreaToDecorationsHint` stays false), so the chrome roles are tagged but not acted on.
      - When maximised, the system keeps its shadow and rounds the window's corners with its own mask.
      - The library's traffic lights and Cmd+W and Cmd+M stay.
      - Why not a borderless window with `hasShadow`: macOS gives a borderless window only a small, tight shadow, unlike other windows, and no native resizing. Avalonia 12.1.6 has no resize drag on macOS (`BeginResizeDrag` does nothing there), so only a resizable window can be resized.
      - Why the client area is not extended: in Avalonia 12.1.6 on macOS the only role acted on is `TitleBar`, which starts the same native drag the library already starts, but its double-click always maximises, ignoring the system setting. The resize and button roles do nothing on macOS.
    - Windows: a native resizable border with the system shadow, and no margin. Snap and snap layouts work natively (the maximise button is tagged as the maximise button). Window corners follow Windows 11 (8 px rounded, not the squircle), on Windows only. The content panel and controls keep their squircles.
    - Linux: the drawn shadow and margin stay. The window's input shape is set to the frame (X shape extension), so the margin is click-through, and `_GTK_FRAME_EXTENTS` tells the window manager the margin, so snapping, tiling and positions use the visible frame. The opaque fallback stays for no compositor.
    - All OSes: the title band, resize grips and window buttons are tagged with Avalonia's chrome roles (`WindowDecorationProperties.ElementRole`), so each OS can handle move, resize and buttons natively where the client area is extended.
  - Adoption:
    - App windows subclass `StandardsWindow` and fill `Title`, `Toolbar`, `Sidebar`, `Content` (shown in the glass panel) and `StatusBar`.
    - `Backdrop` is a public content slot, drawn between the frame's wash and the window content (behind the title band, sidebar, status bar and glass panel). It is empty by default, and glass blurs and refracts it. Continuous animation in it runs at 30 fps unless `HighRefreshRate` is set ([0016](0016-motion.md)).
    - `ContentPanelBounds` is read-only: the glass panel's rectangle in the `Backdrop` slot's coordinates, updated on layout changes, so backdrops can treat the area behind the panel differently.
    - `IsContentScrollable` (default true): the glass panel scrolls its content vertically, with the 12 px padding inside the scrolled content and the scrollbar and shadows at the panel edge. Accepted consequence: content that scrolls itself (a ListBox, a data grid) gets unlimited height and stops virtualising, so apps set `IsContentScrollable="False"` for such content.
    - `WindowButtonStyle` is `Auto`, `TrafficLights` or `CaptionButtons`.
    - The window buttons (`WindowButtons`, `TrafficLightButton`, `CaptionButton`) are public Blocks, so other layouts can use them.
  - Values:
    - Title band 48 high (40 Compact), with the title in Body strong ([0012](0012-type.md)).
    - Status bar 32 high (24 Compact) with 16 px side padding. The library centres any status bar content vertically in the band, not only single text.
    - Sidebar 8 px from the left.
    - Glass panel 8 px from the sides and bottom, with 12 px padding inside.
    - Frame radius 16 with a 1 px border in Fluent's border colour.
    - Drawn shadow (Linux only): blur sigma 8, offset 8 down, black at 25% (light) or 50% (dark).
    - Resize grips 8 px on the edges and 12 px at the corners; the window buttons take precedence over grips.
    - Shadow and margin differ per OS: see Native behaviour.
    - Minimum size 480×320, applied to the frame (on Linux the window adds the shadow margin).
    - When maximised: square corners, no shadow, no grips (on macOS the system keeps its shadow and corner mask: see Native behaviour).
    - Without OS transparency the frame fills the window square, with no shadow.
  - Window buttons:
    - Traffic lights: 12 px dots 8 px apart, 16 px from the left. Close `#FF5F57`, minimise `#FEBC2E`, zoom `#28C840`. Glyphs show on group hover. They are grey with no glyphs when the window is inactive.
    - Caption buttons: 48 px wide, full band height. Close hover uses `DangerFill*` with `DangerForeground` ([0011](0011-colour.md)). Glyphs dim when the window is inactive.
    - Window buttons are not Tab stops (as in native windows); the standard OS shortcuts apply instead: macOS Cmd+W closes and Cmd+M minimises; Windows and Linux Alt+F4 closes. There is no maximise or restore shortcut: macOS has no standard one for zoom, and Win+Up/Down or Super+arrows are handled by the OS shell.
    - When the window is inactive, the traffic lights use the neutral grey `SystemBaseLowColor` and the caption glyphs use the disabled text colour; hover restores the active look. `WindowButtons` has a public `IsActive` property, set by `StandardsWindow`.
  - Tiers ([0004](0004-tier-names.md)):
    - Window buttons (traffic lights, caption buttons) are Blocks.
    - `StandardsWindow` is the shell Module. It holds the frame (which draws the window background, including the backdrop wash below), the title band, the glass content panel, the status bar and a sidebar slot. Its parts are internal, so the layout can evolve.
    - The `Sidebar` Module ([0034](0034-sidebar.md)) plugs into the sidebar slot; with it, the title band shows its button before the title.
    - The app shell Screen (M5) is `StandardsWindow` with the sidebar Module plugged into the slot and the standard content arrangements (sidebar + content, and + inspector), with the collapse stages. Which further Screens follow is an open question ([roadmap](../plan/roadmap.md)).
  - Title band: the title and the toolbar share one band at the top (a unified toolbar).
  - Areas on the window background: the title band, an optional sidebar on the left (a plain list, not a panel) and an optional status bar at the bottom.
  - Content panel:
    - The content sits in one inset glass panel (`GlassBorder`, radius 16; [0015](0015-glass.md)), the only element with the panel look. Where cards may be glass is in [0015](0015-glass.md).
    - It fills the remaining space with `SpacingS` and `SpacingM` gaps ([0013](0013-spacing-and-density.md)), and shrinks to fit beside the sidebar.
    - Layouts: sidebar + content, and sidebar + content + inspector.
  - Backdrop wash (keys `BackdropWash`, `BackdropWashStartColor`, `BackdropWashEndColor`): the window background carries a gentle wash across the whole window, with no visible lines or shapes, so the glass panel reads as glass and text outside it stays calm. It runs from the page colour with the accent mixed in at the top-left (10% light, 14% dark) to the page colour at the bottom-right, and is recomputed for app accents.
  - Contrast: text on the backdrop wash and inside the glass panel meets WCAG AA. The backgrounds that the AA text colours ([0011](0011-colour.md)) are checked against include both the wash's extreme colours and the glass panel's tint laid over those extremes. Both are proven by tests. The guarantee covers the library's own wash and glass. Apps that fill the `Backdrop` slot must keep text over it at AA themselves (as [0020](0020-catalog-app.md) does for the catalog's ribbons).
  - Narrow windows collapse in stages: the inspector hides first, then the sidebar collapses to icons, then to a button that opens it as an overlay. The minimum window size is in Values; the sidebar's widths, thresholds and button are in [0034](0034-sidebar.md).
- **Accepted consequence:** Windows and Linux behaviour is verified only on those machines, not from macOS.
- **Why:** One recognisable window on every OS, with the squircle (except on Windows, see Native behaviour) and glass carried through to the window itself, and a clear focus on the content.
