# 0040 — DataGrid

- **Status:** Agreed, 2026-11-13
- **Decision:**
  - DataGrid comes from the separate package `Avalonia.Controls.DataGrid`, pinned in `Directory.Packages.props` ([0008](0008-target-versions.md), [0010](0010-solution-layout.md)) at 12.1.2. The package is versioned on its own line, not with Avalonia: there is no 12.1.6, and 12.1.2 is the latest 12.1 release (it needs Avalonia 12.1.0 or later).
    - **Why:** The newest release built for the Avalonia 12.1 line the library pins; upgrading it is a deliberate change, like Avalonia's.
  - `StandardsTheme` includes the package's Fluent theme (`avares://Avalonia.Controls.DataGrid/Themes/Fluent.xaml`) right after Fluent, and the Blocks tier restyles it as it restyles Fluent's controls ([0003](0003-restyle-fluent.md)): the DataGrid keeps the package's template, extended; rows, cells and column headers get the library's own templates with the package's part names (`PART_Root`, `PART_CellsPresenter`, `PART_DetailsPresenter`, `PART_RowHeader`, `PART_BottomGridLine`, `PART_RightGridLine`). Apps get it from `StandardsTheme` with no extra step ([0017](0017-app-usage.md)).
    - **Why:** Selection, sorting, editing, keyboard, frozen columns and virtualisation stay the package's; only the look changes.
  - It is a Block ([0004](0004-tier-names.md)): one purpose, showing and editing tabular data, composite inside like ListBox.
  - **Rows** are flat bands across the full width of the grid, 32 high at Normal and 24 at Compact (the list item height, [0024](0024-lists-and-scrolling.md)). Transparent at rest; hover is `ListMedium`; selected is the AA accent fill (`AccentFill*`) with white text (`AccentButtonForeground`), darker on hover; in a disabled grid the selected row takes the disabled accent button's colours. Row background fades are the fixed cross-fades of [0016](0016-motion.md).
    - **Why:** The same colours as list items. A band, not the list's inset squircle pill: a grid is read across cells and columns, its grid lines, vertical lines and current-cell ring run to the cell edges, and sideways scrolling with frozen columns moves the row under a fixed part; a pill's inset rounded ends break the column edges at both sides of the grid. macOS NSTableView's full-width style and the WinUI and Fluent 2 data grids use bands; the comparison render is m3-datagrid-rows.png.
  - No alternating row tint by default. The package (12.1.2) has only `RowBackground`, no `AlternatingRowBackground`; an app can set `RowBackground`.
    - **Why:** The hairlines between rows and the hover band already guide the eye along a row; a tint competes with the hover and selection fills. Windows 11 and Fluent 2 grids have no tint by default.
  - **Grid lines:** horizontal only by default (`GridLinesVisibility` `Horizontal`), 1 px in the border colour (`BaseLow`, the Separator's hairline, [0039](0039-separator-and-gridsplitter.md)), for both directions. The row's line lies over the bottom edge of the row, so a row stays exactly the row height. Vertical lines are an option (`Vertical` or `All`).
    - **Why:** Horizontal lines keep long rows readable; vertical lines are noise until columns of numbers need them. Overlaying the line keeps rows on the 4 px grid (33 px rows would not be).
  - **Column headers:** transparent, Body strong (14 semibold, [0012](0012-type.md)) in the secondary text colour (`BaseMedium`), at the row height, with the density side padding (12, or 8 at Compact). Hover is `ListMedium`, press `BaseMediumLow` (the list's values). A 1 px hairline in the border colour runs under the header row. The separators between headers show only with vertical grid lines.
    - **Why:** Weight and colour set the header apart from the regular-weight data without a fill (Fluent 2's header weight; the secondary colour as in macOS). Header separators follow the grid's own vertical lines, so the header row reads as one strip like the rows below it.
  - The sort caret is `Icons.CaretUp` (ascending) or `Icons.CaretDown` (descending), 16 px at both densities, `SpacingXS` after the header text, in the header's text colour; unsorted columns show none. The text is cut short before the caret is.
    - **Why:** Next to the label the caret reads as part of it, as in Fluent 2. 16 px follows the field-button icon exception of [0027](0027-text-input.md): a 20 px caret beside 14 px text is heavier than the text.
  - **Resize grip:** within 5 px of a header edge that resizes a column (the package's resize zone: the right edge resizes that column, the left edge the one before), a pill grip shows at that edge, 4 px wide and the header height less `SpacingXS` above and below (24, or 16 at Compact), in the scrollbar thumb's hover colour, and its drag colour while resizing. It fades over the scrollbar's fixed `MotionFast` transitions, never shows in a disabled grid, and shows only where the grid and column allow resizing (`CanUserResizeColumns` is off by default in the package).
    - **Why:** The GridSplitter's grip ([0039](0039-separator-and-gridsplitter.md)): a draggable edge reads the same everywhere, invisible until the pointer reaches it.
  - **Cells:** transparent, Body text, the row height. A text column's text has the density side padding, is centred vertically and is cut short with an ellipsis. An invalid cell gets a 1 px border in the danger colour; an invalid row keeps Fluent's 0.4 tint, in the danger colour.
    - **Why:** Cell text lines up with the header text; the danger colour is the library's error colour ([0027](0027-text-input.md)).
  - **Cell focus:** the current cell shows the focus ring ([0019](0019-focus-ring.md)), 2 px, `CornerRadiusControl`, inset 2 px inside the cell, while the grid is used from the keyboard: after Tab or arrow focus into the grid, or any key pressed in it, until a pointer press or focus leaves the grid. On a selected row the ring takes the selected text colour (white). There is no ring in edit mode; Fluent's two-tone cell focus rectangle and the grid's own focus adorner are dropped.
    - **Why:** Inset, the ring is never clipped by the row, the grid or neighbouring cells. The keyboard rule is how browsers decide `:focus-visible`: arrow keys move the current cell without moving focus, so focus alone cannot say whether the keys are in use. The accent ring would vanish on the accent band; white meets 4.5:1 on every selected fill ([0011](0011-colour.md)).
  - **Editing** a text column turns the cell into a TextInput field ([0027](0027-text-input.md)) filling the cell: the row height is the field height, `CornerRadiusControl`, the 1 px accent border on focus, and padding one less than the cell's side padding (11,4 or 7,2) so the text stays where it was. On a selected row the 1 px border takes the selected text colour (white) instead of the accent; an error border stays the danger colour. The field shows no ring of its own; validation errors use Fluent's tooltip.
    - **Why:** The edited cell is a real field, with the border marking where typing goes ([0027](0027-text-input.md)); on the accent band an accent border would vanish, and white keeps the edited cell outlined. The text does not jump when editing starts.
  - **Check columns** use the library CheckBox ([0030](0030-checkbox-toggleswitch-radiobutton.md)), centred in the cell as the package places it. The cell check look below applies to a check box that is a cell's own content (a check column's, or the root of a template column's cell template); check boxes nested inside an app's cell template keep the plain CheckBox look. Outside editing the package shows a disabled check box; it keeps the enabled look, and takes the disabled look only in a disabled grid. On a selected row the check box inverts in the selected text colour: a white outline, or a white box with an accent mark.
    - **Why:** A read-only grid should not look disabled. On the accent band the accent box and the grey outline would vanish; the inverted pair keeps both states readable, as macOS does for selected rows. **One-off exception under [0007](0007-restyle-scope.md):** these are existing colours (`AccentButtonForeground`, `AccentFillColor`) in a new combination, for check boxes on a selected row only.
  - **Combo columns** (a template column with a ComboBox in its editing template) use the library ComboBox ([0028](0028-combobox.md)), stretched to fill the cell like the text field.
  - **Scroll bars** are the overlay bars ([0025](0025-overlay-scrollbar.md)) at their own thickness, over the rows; the corner square between them is not drawn. The grid has no scroll-edge shadow: it scrolls without a ScrollViewer, and the header hairline marks its top.
  - **Frozen columns** look the same as the rest: the row band, lines and selection run through them, and columns scrolled under them are clipped (the package's behaviour). **Row details** sit on the row's band, transparent, so selection covers them too. **Row headers** stay hidden by default (`HeadersVisibility` `Column`, Fluent's default); shown, they keep Fluent's look with their separators in the border colour.
    - **Why:** A frozen column and a row's details belong to the same row; row headers add a column most grids do not need.
  - The DataGrid itself is transparent, with no border, `CornerRadiusControl` and its content clipped to that squircle, like the ListBox ([0024](0024-lists-and-scrolling.md)). Disabled, its text and headers take the disabled text colour; Fluent's disabled wash is dropped. Read-only looks the same as editable.
    - **Why:** The grid sits on the page, card or glass panel like a list; disabled matches every other Block's dimmed text.
  - The catalog sidebar shows the page with Phosphor `table`, added under [0026](0026-icon.md)'s rule for adding an icon.
- **Known for later steps:** row group headers (grouping) keep the package's Fluent look (15 px text, `ChromeMedium` fill).
- **Why:** A data grid that reuses the list's rows and colours, the field and check box Blocks for editing, and the library's focus ring, grip and scroll bars, while every behaviour stays the package's.
